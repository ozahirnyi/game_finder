# Background library catalog matching

**Goal:** Keep explicit catalog lookup running when the user leaves Library, with visible loading and saved progress/results.

**Design:** Reuse durable BackgroundJob + ARQ, never browser-only state. Starting matching snapshots owner-scoped eligible IDs, source and the correction option. Each delivery processes up to ten games with the existing read-only matcher, saves accumulated proposals and counts, then requeues remaining work. Queue recovery handles broker interruptions. Latest-job polling restores the job/results across navigation and reload. Nothing links until the existing explicit apply/uncertainty confirmation. After apply, dismiss the saved preview to prevent restoring stale decisions. Starting a fresh job replaces prior terminal results. Active jobs are reused per owner/source, including across double-clicks.

**UI:** Spinner, native progress bar, checked/total, games with suggestions, and remaining count; explain that leaving the page is safe. Automatically reveal active or completed pending review when returning to PlayStation. Keep failed tasks retryable. Clarify title-only AI assistance and rename the checkbox to “Recheck already matched games”, with an explanation of its default-off behavior.

**Implementation:** New `app/library_catalog_jobs.py` handles selection, progress and one bounded delivery. Add start/current/dismiss endpoints in `app/main.py`; register operation and continuation in `app/worker.py`. Existing BackgroundJob JSON fields suffice; no schema/model migration. New API functions and a shared query hook drive `LibraryCatalogMatches` and its launcher. Inline execution only.
